# Подготовка изолированного сервера Horizon 26.3

Владелец явно принял Minecraft EULA для изолированного серверного теста
ответом «Да» в текущей сессии. Согласие не подтверждает вход Microsoft или
наличие игровых ресурсов. Повторное подтверждение того же теста не требуется.
Существующий NeoForge-сервер и его миры для эксперимента не используются.

## Нативные инструменты

Workflow `horizon-native-runtime.yml` собирает из официального Horizon
`c78187dffffb60f31517eadcb87413386e8ce729` четыре Linux x86-64 инструмента:
`horizon-engine`, `horizon-prepare`, `horizon-server`, `horizon-ctl`.
Сборка `fast --locked --no-default-features` отключает звук, контроллеры
и необязательные сетевые возможности движка. Временный CI-артефакт содержит
исполняемые файлы, LICENSE, research-lock.json, контрольные суммы и отчёт.
Minecraft, ресурсы сторонних модов, учётные данные и миры в него не входят.
Это инструменты разработчика, не новый установщик и не релиз модпака.

`--help` и `--launch-api` проверяют лишь загрузку исполняемых файлов.
Даже успешный workflow **не означает запуск сервера или рабочего Horizon-модпака**.

## Что требуется для настоящего запуска

1. Подготовленная владельцем папка ресурсов **26.3**. Официальный
   `horizon-prepare` импортирует файлы установленной Minecraft; сам игру не скачивает.
   Подготовку можно выполнить в официальном Horizon Launcher на своём компьютере.
   Сервер не требует входа игрока Microsoft, чтобы просто загрузить мир, но требует
   подготовленные файлы. Для игрового клиента сохраняется проверка лицензии
   официальным launcher; её не обходим. Пароли и токены передавать не нужно.
2. Вся подготовленная папка, включая `horizon-resources.json`,
   `horizon-prepare.json`, `facts.json`, `block-tags.json`, `registries.json`,
   `commands.json`, текстуры и шрифты. Перечисление не исчерпывающее: движку нужны
   и остальные результаты подготовки. Для подготовки исходных файлов нужен Java 25;
   готовый нативный сервер Java для игры не запускает.
3. Шесть content-модулей из совместного workspace: четыре YUNG's, Terralith,
   `techquest_yungs_shared`. Их отдельно проверяет официальный SDK; текущая проверка
   сборки движка их не загружает и не публикует.
4. Новая отдельная папка теста, только loopback, whitelist и `online-mode=true`.

## Предварительная проверка разработчика

Из корня репозитория (это **не пользовательский способ установки**):

```bash
python horizon/tools/server_preflight.py \
  --resources /path/to/prepared/26.3 \
  --tools /path/to/native-tools \
  --work /path/to/five-together \
  --server-dir /path/to/new-isolated-test \
  --accept-eula
```

Скрипт только читает: не запускает процессы, ничего не скачивает, не пишет
`eula.txt`, не меняет ресурсы и миры. Он проверяет версию/схему подготовки,
два записанных SHA-256 производных файлов, наличие основных ресурсов,
происхождение и SHA-256 инструментов, манифесты модулей, владельцев namespace
и отдельную пустую папку теста. Возвращает 2 при проблемах. Вывод не включает
абсолютные пути и содержимое игровых файлов. Самописные JSON или тестовые
fixtures не заменяют официальную подготовку и **не доказывают право владения**.

Даже `preflight_passed=true` не является полной проверкой ресурсов, SDK,
запуска мира или портирования. Нужны реальная загрузка всех шести модулей,
`Done`, сохранение, штатная остановка и повторное открытие мира; затем вход
лицензированного клиента, генерация структур, мультиплеер и замеры нагрузки.
Не использовать `--benchmark` как проверку модов: он их не загружает.

## Оставшаяся граница PR #8

Даже успешно запущенный сервер с шестью модулями данных не переносит
Java-механики Create/IC2/Incoming и остальных компонентов. Их реализации
и игровые испытания остаются отдельной большой работой. PR #8 остаётся draft,
пока не выполнен выбранный владельцем критерий работающего Horizon-модпака.
