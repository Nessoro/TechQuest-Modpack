# TechQuest 0.3.3-micro3 — удалить только RPG Core

**Статус:** кандидат на следующий микропатч, не опубликован. Основа — micro2; Minecraft Java 1.21.1, NeoForge 21.1.264, Java 21.

## Решение владельца
- **Убрать** `TechQuest RPG Core 0.1.0` (`techquest-rpg-core-0.1.0.jar`) из **будущих** сборок и установщиков.
- **Оставить** `TechQuest Compatibility 1.0.0` (`techquest-compat-1.0.0.jar`), включая:
  - совместимые рецепты Create ↔ IC2;
  - клиентский обход проблемы ранней загрузки Better Zoom.
- Другие RPG-моды, FTB Ultimine, Physics Mod, оригинальные технологии и руководство Patchouli — без изменений.

## Изменения в цепочке сборки
Генератор `build_pack.py` формирует Compatibility как собственный JAR, добавляет его в `.mrpack`, клиентский и серверный наборы. Функция упаковки RPG Core отключена. Клиентский и серверный установщики продолжают поставлять Compatibility и больше не принимают RPG Core как штатный компонент. Windows GUI встраивает Compatibility из проверенного пакета; при обновлении старого профиля `mods` заменяется атомарно с откатом. Старые JAR уходят в общую резервную директорию `.techquest-previous-mods`.

**Важное ограничение:** устанавливая новую версию, не переносите вручную старый `techquest-rpg-core-0.1.0.jar` из предыдущей `mods` / бэкапа обратно в активную папку. Пользовательские `saves`, `options.txt`, `config`, карты и профили Minecraft Launcher не удаляются. Прогресс или старые серверные scoreboard от RPG Core могут остаться в мире, но после удаления JAR его функции уже не выполняются.

## Проверка будущего пакета
- В клиентском и серверном `mods` **есть** `techquest-compat-1.0.0.jar`.
- В клиентском и серверном `mods` **нет** `techquest-rpg-core-0.1.0.jar` и `pmmo-*.jar`.
- В `.mrpack` **есть** `overrides/mods/techquest-compat-1.0.0.jar` и **нет** `overrides/mods/techquest-rpg-core-0.1.0.jar`.
- Проверить реальные рецепты Create/IC2 и работу зума после запуска игры. CI-тесты и сборка JAR не подтверждают игровой запуск и не доказывают, что ошибка разрушения блоков вверх устранена.

## Распространение
Этот PR **не** изменяет ранее опубликованный `v0.3.3-micro2-preview` и **не** создаёт новый публичный релиз автоматически. Публиковать micro3 следует только после успешного CI и отдельного решения о выпуске. Текущая цель — корректно исключить RPG Core без потери Compatibility. Перед тестом в существующем мире сделайте резервную копию.

## Обновление управляемого профиля и откат (micro3)
- Для обычных игроков: запустить GUI `TechQuestInstaller.exe` **этой же ревизии** и указать существующую папку TechQuest; нельзя выбирать общую `.minecraft`. Ранее установленный профиль должен иметь маркер TechQuest. Подтвердить замену модов. Заранее закрыть игру и сохранить отдельную копию важного мира.
- Для клиентского и серверного Python-bootstrap разработчика: скачивание и проверка всех JAR проходят во временной `.techquest-download-*` рядом с профилем; только после успеха заменяется каталог `mods`. Архив bootstrap должен включать `scripts/mods_transaction.py`.
- Предыдущий активный набор хранится **только** в `.techquest-previous-mods/`. Повторное обновление перезаписывает эту резервную копию только после успешной подготовки новой; если активация или запись служебных файлов завершается с ошибкой, старые активные моды и предшествующий бэкап возвращаются на место.
- При неожиданном прерывании процесса может остаться временная `.techquest-backup-rotation/`. Следующая установка блокируется, пока владелец не проверит содержимое; **не удаляйте** эту папку вслепую. Для ручного возврата к предыдущей версии закройте Minecraft и сервер, переместите текущую `mods` в отдельную диагностическую папку и переименуйте `.techquest-previous-mods` в `mods`. Проверяйте согласованность версий у всех участников сервера.
- Существующие `saves`, `world`, `config`, `options.txt`, локальные карты, `server.properties`, `eula.txt` и данные Minecraft Launcher не удаляются. Ручные JAR, которых нет в актуальном манифесте (включая AMW), не копируются автоматически; их нужно оценивать отдельно. Устаревшие RPG Core и PMMO обратно не переносить.
- Ошибка добычи блоков вверх исследуется отдельно при отключённом Ultimine, затем с Ultimine и Physics Mod: отказ от RPG Core не считается её исправлением.

## Критерии подтверждения
- Unit-тесты: `python -m unittest discover -s tests -v`.
- Полная сборка: `python build_pack.py`; проверка хешей загрузок и состава: `python scripts/audit_micro3_packages.py` и `scripts/security_audit.py` в CI.
- Windows: `dotnet publish`, `TechQuestInstaller.exe --self-test`, реальная установка/обновление пробного управляемого профиля, откат с искусственной ошибкой.
- Игра: фактическое меню, новый мир, рецепты Create–IC2, Better Zoom, затем сервер до `Done` и подключение клиента **только после самостоятельного согласия владельца с EULA**.
- До этих испытаний статус остаётся **кандидат, не проверен в игровом runtime**. Публикация и объединение PR — только по явному разрешению владельца.
