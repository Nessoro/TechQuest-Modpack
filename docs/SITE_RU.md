# Сайт TechQuest

Адрес: **https://nessoro.github.io/TechQuest-Modpack/**. Это существующий GitHub Pages из `main/docs`, отдельный сайт/хостинг не создаётся. Изменения из PR публикуются Pages только после слияния в main.

Новый дизайн — светлый полевой дневник с зелёной картой экспедиции: приключения, понятная установка, каталог, обратная связь, FAQ и план. Иллюстрация `frontier.svg` и favicon созданы для проекта, сторонние изображения и внешние шрифты не подключаются. JavaScript/CSS разделены для поддержки, сборщик фронтенда не нужен.

Сохраняются поиск/фильтры, обе формы черновиков Issues и лента открытых задач. Данные API выводятся через textContent; на сайте нет токенов и фоновой публикации обращений. При недоступном GitHub API остаются прямые ссылки. Без JavaScript работают инструкция, скачивание через Actions и ссылка на исходный список модов.

## Версия и скачивание

`python scripts/sync_site_mods.py` синхронизирует каталог и `window.TQ_PACK` из modlist.json. Он не выполняет обновление модов. 70 позиций каталога включают компоненты и кандидатов, это не число JAR собранного профиля.

Сайт запрашивает последний успешный Build TechQuest alpha **ветки main**, затем проверяет наличие неистёкшего Windows GUI artifact. Если он доступен, кнопка ведёт к этому артефакту. При ошибке/лимите API/отсутствии файла остаётся ссылка на список сборок. Для скачивания Actions artifacts нужен аккаунт GitHub; срок хранения ограничен. Публикация постоянных релизных файлов и обновляющийся установщик остаются в #21. Сайт не объявляет альфу стабильной по зелёному CI.

## Как найти сайт в GitHub

В начало README добавлены крупный заголовок-ссылка и отдельные переходы к установке, каталогу и обратной связи. Ссылка также есть в русской инструкции и contact links формы Issues.

Дополнительная точка входа: главная страница репозитория → **About → шестерёнка → Website** → `https://nessoro.github.io/TechQuest-Modpack/`. Это отдельное свойство GitHub, оно не заполняется коммитом README. Не менять источник Pages или видимость репозитория ради ссылки.

## Проверка

`.github/workflows/validate-site.yml` проверяет синхронизацию и JavaScript, запускает Chromium/Playwright и сохраняет скриншоты. Разработчик может выполнить `python scripts/check_site_browser.py` с установленными Playwright/Chromium; игроку они не нужны.

Проверяются ширины 360/390/768/1024/1440, отсутствие горизонтального переполнения, раскрытие каталога, поиск/пустой результат/фильтр, обе формы без отправки сообщений, безопасный текст из API, внутренние якоря, успешный и недоступный API, работа основных ссылок без JavaScript. API в этих проверках подменяется контролируемыми ответами: это не проверка доступности опубликованного GitHub Pages. Локальный внешний вид проверяется по настоящим скриншотам браузера.
