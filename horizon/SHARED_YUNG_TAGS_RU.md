# Следующий этап Horizon: один владелец yungsapi

Источник обновлён до NeoForge main `918b4bf` и успешного Build `42597702544`. Старые цифры 86 компонентов / 5 partial относятся к прежнему снимку. Основная сборка в main не меняется.

## Что реализовано

Официальный `horizon-port-pack` на закреплённом upstream `c78187d` исключает namespace, на который претендуют несколько модов. В проверенных SHA-512 оригиналах Better Dungeons и Better Nether Fortresses найдены по два одноимённых `data/yungsapi/tags/worldgen/structure/*.json`. Это не одинаковые копии: первые содержат `betterdungeons:small_nether_dungeon`, вторые — `betterfortresses:fortress`.

`tools/assemble_shared_yung_tags.py` собирает их в один локальный content-модуль `techquest_yungs_shared` с `namespaces = ["yungsapi"]`. Оба итоговых тега содержат обе структуры, в исходном порядке, без повторов. При несовместимом `replace: true`, неизвестном формате, занятом namespace, symlink или уже существующей папке результат не перезаписывается молча. Исходные файлы остаются неизменными.

Скрипт также перечисляет **все** файлы каждого `outside/` с namespace и статусом. Четыре восстановленных источника отмечаются отдельно; остальные требуют разбора. Это не объявление, что оставшиеся файлы можно без последствий отбросить. В отчёте только метаданные/хеши; JAR, исходные ресурсы и hmod не публикуются. Производные теги сохраняют LGPL-3.0-only источников.

## Проверки

- Девять unit-тестов Port Lab, включая объединение значений, сохранение оригиналов, ошибки до записи и отказ от перезаписи чужого namespace.
- Локальная сборка двух итоговых тегов из четырёх файлов оригинальных JAR после сверки SHA-512 с текущим main — значения обоих модов сохранены.
- Combined workflow повторно импортирует актуальный mrpack, выполняет официальный carry и сборку shared-тегов, затем проверяет **6 content-модулей** официальным SDK: пять исходных и один общий. Это по-прежнему пять исходных модов, а не шесть полностью портированных Java-модов. Результат отмечается только после успешного CI.

Восстановлены данные, а не Java-обработчики YUNG API. Реальная генерация структур, действие тегов, совместная загрузка в Horizon, сохранения и сервер ещё не проверены. Все runtime/gameplay флаги остаются false.
