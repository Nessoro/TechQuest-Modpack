# Исправления совместимости TechQuest

## Проверка кандидата 0.3.3 перед игровым запуском

- `python scripts/audit_jar_metadata.py` (Python 3.11+) проверяет готовые клиентские и серверные JAR,
  обязательное наличие модов и диапазоны Minecraft/NeoForge, включая объявленные Jar-in-Jar.
  Отчёт `jar-metadata-audit.json` прикладывается к артефакту сборки. Все межмодовые диапазоны
  версий, mixin и производительность этой проверкой не подтверждаются.
- Диапазоны `[1.21,1.21.1)` в JEI, More Culling и Puffish Skills **сами по себе не конфликт**:
  FML **4.0.45**, входящий в NeoForge **21.1.264**, допускает Minecraft `1.21` и NeoForge
  `21.0.166` через штатную `VersionSupportMatrix`. Это проверено по исходнику
  [loader-4.0.45-sources.jar](https://maven.neoforged.net/releases/net/neoforged/fancymodloader/loader/4.0.45/loader-4.0.45-sources.jar),
  `net/neoforged/fml/loading/VersionSupportMatrix.java`. Исключение не переносится на другие версии загрузчика.
- Terralith объявляет обязательный Lithostitched на `BOTH`. Общая серверная метка Modrinth
  раньше исключала библиотеку из клиента. Проверенный оригинальный Lithostitched **1.8.0**
  (`sPmtDq1X`, MIT, Minecraft `[1.21,1.21.1]`, со встроенной Apollib) закреплён и явно устанавливается
  на обе стороны для обычного одиночного мира и мультиплеера. Сторонний JAR не изменяется.
- У Forgematica 0.4.3 автор пометил `-sources.jar` как primary. Резолвер теперь исключает
  sources/javadoc и выбирает настоящий `forgematica-0.4.3+mc1.21.1.jar` из того же релиза.
  Хеши берутся из записи выбранного файла Modrinth; JAR не перепаковывается.
- Все клиентские способы установки получают одинаковый `options.txt` из `.mrpack`:
  `graphicsMode:0` (Fast), 6/5 чанков, лимит 60 FPS. GUI больше не дублирует настройки в коде;
  существующий пользовательский `options.txt` сохраняется. Реальный выигрыш FPS не измерен.
- Серверный комплект и bootstrap получают также определения книги Patchouli; smoke-test копирует
  книгу и Open Loader config. Оба bootstrap-архива проверяются после извлечения в изолированную папку.

Кандидат **не проверен запуском Minecraft**. EULA не принимается автоматически;
после успешного полного CI требуется ручной игровой тест из `docs/INSTALL_0.3.3_PC_RU.md`.

Исправления рассчитаны на Minecraft 1.21.1 / NeoForge 21.1.264 и IC2 Nostalgia
21.1.0-local.26. После обновления модов нужно повторять серверный и клиентский тесты.

## Версии зависимостей и Optimized

В 0.3.3 альфа **Iris не установлен**. Sodium остаётся в едином оптимизированном клиенте; принудительно выбирать старую версию Sodium из PR #4 не нужно. Сборщик учитывает точный `version_id` обязательных транзитивных зависимостей, поэтому не подставляет несовместимую последнюю версию. Create 6.0.10 и Superb Warfare 0.8.9.2 закреплены по Modrinth version ID.

Повторная сборка очищает старые JAR **только в генерируемых** `output/client/mods` и `output/server/mods`. Пользовательские каталоги Windows Launcher не затрагиваются.

## Create и IC2 Nostalgia

`techquest-compat/` содержит исходники нашего мода с ресурсами без Java-кода.
Сборщик создаёт `techquest-compat-1.0.0.jar`, устанавливает его клиенту и серверу
и помещает в `overrides/mods/` внутри `.mrpack`. Штатный серверный и клиентский установщики, включая Windows GUI, также извлекают этот мод. Он загружается после Create и IC2, поэтому исправления
применяются ко всем мирам, включая уже существующие.

- Шесть рецептов плавки/переплавки Create заменяют неверные `ic2:ingot_tin`,
  `ic2:ingot_silver`, `ic2:ingot_uranium` на `ic2:tin_ingot`,
  `ic2:silver_ingot`, `ic2:uranium_ingot`.
- Два рецепта для `ic2:ingot_aluminium` отключены: такого слитка в используемом
  IC2 Nostalgia нет. Рецепты алюминия для других модов не изменяются.
- Create закреплён на проверенном выпуске 6.0.10 (`UjX6dr61`).

## Superb Warfare на выделенном сервере

В оригинальном Superb Warfare 0.8.9.2 (`bl7W8fjU`) `ClientLevelMixin` указан
одновременно в общем списке `mixins` и клиентском списке `client`.
Сервер пытается загрузить клиентский класс и пишет ошибку `invalid dist`.

После проверки SHA-512/SHA-1 исходного скачивания сборщик и серверный установщик
локально удаляют только запись `ClientLevelMixin` из общего списка в
`mixins.superbwarfare.json`. Клиентский список и все остальные записи JAR
остаются неизменными. Повторное применение безопасно. Неожиданная структура
конфига и подписанные JAR отклоняются.

В репозитории нет изменённого стороннего JAR. Клиент и download manifest
используют оригинальный файл автора. SHA серверной производной копии отличается
от SHA исходного скачивания: это ожидаемый результат исправления. Для установки
сервера используйте `scripts/install_server.py` или `output/server`, поскольку
обычный импорт `.mrpack` сторонним серверным инструментом не применит этот шаг.

## Проверки

`python -m unittest discover -s tests -v` проверяет точные зависимости, упаковку
рецептов, их установку на сервер и точечное изменение mixin-конфига.
`python build_pack.py` собирает клиент и сервер с проверкой хешей скачиваний.
Workflow `smoke-server.yml` отклоняет повторное появление исправленных ошибок
рецептов и `ClientLevelMixin`, даже если сервер достиг состояния `Done`.

Графический запуск, шейдеры, подключение игроков и длительная игра требуют
отдельной проверки. Успешный серверный smoke-test не подтверждает их.

## Статус переноса в 0.3.3

Код портирован из исторического PR #4 для NeoForge 21.1.259. Его исходные результаты (в `compat/VALIDATION.md`) **не означают** проверку Minecraft-клиента или сервера 0.3.3 / NeoForge 21.1.264. Unit-тесты, сборка и антивирусный аудит выполняются в новом PR #5. Отдельный серверный workflow `smoke-server.yml` требует явного принятия EULA оператором.
