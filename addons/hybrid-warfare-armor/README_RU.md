# TechQuest Hybrid Warfare — original Superb Warfare + energy tech upgrade

**Версия аддона:** 0.2.8-SNAPSHOT (экспериментальная). Minecraft **1.21.1**, NeoForge **21.1.264**, Java **21**. Изменения в **draft PR #51**, в `main` и установщик TechQuest не добавлены. **Не проверено запуском Minecraft.**

## Исправление 0.2.7 — энергетический нагрудник не принимался в верстаке

По результатам игрового теста 22 ноября 2026 года верстак оставлял результат
пустым при вводе `IC2 Quantum — Russian 6b43 Chest` + обычная элитра.

**Причина:** в 0.2.6 `PoweredElytraEnergy.isPoweredChest()` проверял
`stack.getEquipmentSlot() == EquipmentSlot.CHEST`. Но в NeoForge 1.21.1
`ItemStack.getEquipmentSlot()` — это необязательный override и по умолчанию
возвращает `null` **даже на реальных экземплярах ArmorItem**. Из-за этого
валидная 6Б43 с компонентом `techquest_hybrid:technology=ic2` отвергалась
*до проверки батареи*, хотя имела заряд 2.05k / 10m.

**Исправление:** теперь определяется исходный слот через необязательный
`ItemStack`-override, а при отсутствии — через
`stack.getItem() instanceof ArmorItem` и
`ArmorItem.getEquipmentSlot()`. Проверки наличия энергетической технологии,
установленной элитры и настоящей доступной батареи остаются прежними.
Регрессионный тест предотвращает повторное появление проверки
`null != CHEST`.

**Сценарий:** в тестовом мире убери 0.2.6 и установи только
`techquest-hybrid-warfare-0.2.7-SNAPSHOT.jar`. В обычный верстак 2×2/3×3
положи оригинальную 6Б43, уже объединённую с IC2 Quantum Chestplate, и
исправную элитру. Выход должен показать тот же 6Б43 с новым компонентом
элитры. Проверь, что простой негибридный 6Б43 и обычная ванильная броня
по-прежнему не принимаются.

**Сборка CI и компиляция** не заменяют игровой тест рецепта и полёта.

## Версия 0.2.8 — отображение рецепта энергетической элитры в JEI

**Игровая проверка пользователя:** на 0.2.7 обычный верстак успешно
превращает `IC2 Quantum — Russian 6b43 Chest` + элитру в улучшенный
нагрудник, но JEI показывает только рецепты **других модов**, не
`techquest_hybrid:powered_elytra_attach`.

**Причина:** `PoweredElytraRecipe extends CustomRecipe` — его входы,
разрешённые типы брони, заряды и результирующие компоненты определяются
для каждого реального ItemStack. Обычный JEI не показывает
`isSpecial()` recipe с пустыми `getIngredients()` /
`getResultItem()`.

**Решение:** добавлена *необязательная* интеграция
`dev.techquest.hybrid.jei.PoweredElytraJeiPlugin` для версии JEI
`19.64.0.455` из TechQuest. Она создаёт **только в интерфейсе JEI**
образцы рецептов с оригинальной ванильной элитрой и энергетическими
`superbwarfare:ru_chest_6b43`/`us_chest_iotv` после улучшения
IC2, MI, Mekanism, Oritech и оригинальным IC2 Quantum Chestplate.
Для каждого варианта отображается соответствующий **исходный нагрудник**
с технологическим донором и нагрудник с компонентом
`techquest_hybrid:elytra_attachment` в результате. Это именно
образцы, а не новая система крафта или доказательство работы сторонних
энергосистем.

Код JEI начинает показывать примеры **только если реальный
`PoweredElytraRecipe` присутствует в локальной таблице рецептов**;
при отключении его датапаком примеры также исчезают. Все исходные
ограничения крафта остаются: реальный заряд, поддерживаемая энергетическая
броня, единственная элитра. Повторное улучшение не допускается.

**Важно:** версии JEI **не обязательны** для запуска аддона, потому
что API подключается `compileOnly` и в JAR не упаковывается. В JEI
нажми `U` по элитре (применение) или `R` по 6Б43; отображаемые
образцы предназначены для подсказки и могут не воспроизвести заряд,
чары и произвольные компоненты конкретной брони — фактический крафт
продолжает копировать исходный предмет вместе с данными.

**Не проверено запуском Minecraft:** требуется увидеть категорию
`Crafting` с примерами энергетического улучшения в JEI после
установки JAR 0.2.8 в тестовом клиенте, в котором есть JEI.

## Версия 0.2.7 — исправлена совместимость рецепта элитры с 6Б43

После проверки игроком 0.2.6 обнаружено: гибридный нагрудник
`IC2 Quantum — Russian 6b43 Chest` отображает реальный заряд
`2.85k/10m`, но при помещении нагрудника и ванильной элитры в верстак
результат остаётся пустым.

В 0.2.7 обработка рецепта сначала **строго распознаёт по ID**
`superbwarfare:ru_chest_6b43` и `superbwarfare:us_chest_iotv`;
проверяет наличие `techquest_hybrid:technology` и подтверждённую
ёмкость энергии, и только после этого переходит к общим API определения
слота. Такое разделение исключает ошибочный отказ модовой брони
из-за несовпадения `getEquipmentSlot()` с обычными ArmorItem.

**Не изменено:** запрет на обычные неэнергетические нагрудники,
потребление реального заряда вместо износа элитры, защита от повторной
установки и сохранение оригинального предмета.

**Примечание:** этот фикс направлен на распознавание нагрудника.
Если рецепт всё равно пустой, нужен `latest.log` этой сессии:
проверим, загрузил ли Minecraft серверный
`techquest_hybrid:powered_elytra_attach` JSON, не изменив состояние
самого предмета. Клиентское JEI может не отображать динамический рецепт.

## Версия 0.2.6 — встроенная элитра только в энергетические нагрудники

**Цель:** объединить оригинальную элитру с реальным энергетическим нагрудником и
получить **обычное планирование на элитре, которое не расходует её прочность**.
Вместо повреждения элитры каждый тик полёта списывается энергия нагрудника.

### Установка

Открой обычный верстак 2×2 или 3×3. Положи **одну исправную ванильную элитру
+ один энергетический нагрудник** (в любом порядке). Получится тот же
нагрудник, но с сохранённым компонентом
`techquest_hybrid:elytra_attachment`. Исходная броня остаётся того же типа
и с тем же ID, уровнями заряда, исходным донором, чарами, аффиксами,
прочностью и произвольными данными.

Разрешены:
- Нагрудник **TechQuest Hybrid Warfare 6Б43 или IOTV** только после
  установки энергетического улучшения IC2, MI, Mekanism или Oritech. Обычный
  Superb Warfare без улучшений **не подходит**.
- Нативные электрические нагрудники IC2, которые действительно возвращают
  ёмкость через `ElectricItem.manager`.
- Другие энергетические нагрудники, имеющие реальный NeoForge
  `Capabilities.EnergyStorage.ITEM` с ёмкостью и разрешённой выдачей энергии
  `extractEnergy`; это определяется фактическим предметом, а не по имени мода.
  **Некоторые** MekaSuit/MI/Oritech предметы могут иметь собственную энергосистему,
  которая не допускает внешнюю выдачу FE — для них нужен отдельный адаптер;
  они не будут ошибочно выдавать бесплатный полёт.

Запрещено: обычная алмазная/незеритовая и прочая неэнергетическая броня,
повторная установка второй элитры, поломанная элитра без возможности
нормального полёта.

### Энергетика и поведение

- **Стоимость:** 200 единиц энергии **за тик планирования**
  (4 000 за секунду при 20 TPS); скорость и управление — ванильные.
- При старте и каждую следующую игровую итерацию полёта проверяется реальный
  доступный заряд. **Когда энергии меньше стоимости тика, планирование
  прекращается**. Встроенная элитра не может обеспечивать бесплатный полёт.
- **Прочность самой элитры и нагрудника от полёта не уменьшается.**
  Обычный урон броне при сражении и падении не отключён.
- Квантовый гибрид 6Б43 расходует заряд **сохранённого IC2 Quantum Chestplate**,
  тот же источник, который заряжается через MFSU. Для других гибридов
  используется текущая встроенная FE-ёмкость. Нативные IC2 предметы используют
  родной IC2 менеджер; остальные совместимые энергонагрудники — NeoForge FE.
- Крылья рендерятся из исходной ванильной модели и текстуры элитры.
  Новые 3D-модели и изображения не добавлены. Оригинальная текстура брони
  сохраняется. Слои игрока регистрируются на клиенте.
- Исходный IC2-джетпак и его клавиши **не меняются**. Комбинированное
  использование джетпака и планирования подлежит проверке в игре; оба
  механизма могут расходовать энергию по собственным правилам.
- **Отсоединение элитры пока не реализовано** — не применяй эту
  экспериментальную версию к ценной броне без резервной копии мира.

### Проверка

1. Удали прежний JAR аддона и установи только `0.2.6-SNAPSHOT`.
2. В тестовом мире попробуй обычный незеритовый нагрудник + элитру:
   **рецепта быть не должно**.
3. Объедини гибридный 6Б43 с энергией и обычную элитру; сохранилась ли
   оригинальная военная броня, дата-компоненты и заряд?
4. Взлети с высоты (обычным двойным нажатием прыжка в падении), проверь
   снижение энергии **4 000/с**, отсутствие потери прочности элитры.
5. При разряде планирование должно прекратиться; затем заряди 6Б43
   в MFSU и проверь, что элитра снова работает.
6. Повтори с ванильной квантовой бронёй IC2, затем с реально
   FE-совместимой бронёй другого мода.
7. Перезайди в мир и перепроверь крылья, энергию, заряжание,
   original Superb Warfare/Apotheosis и управление IC2 джетпаком.
8. Для выделенного сервера нужен тот же JAR; проверить синхронизацию
   полёта и энергокомпонента по клиенту/серверу.

**Не проверено запуском Minecraft:** Gradle, Python и GitHub Actions
проверяют сборку, а не реальные физику полёта, размещение крыльев и совместимость
других модов. Не добавлять в `main`/официальный установщик без ручного теста.

## Версия 0.2.5 — полноценный квантовый шлем на базе 6Б47

**Причина:** в 0.2.4 зарядка через IC2 и встроенный донор уже поддерживали шлемы, но часть функций оригинального `ic2:quantum_helmet` вызывается только из `ItemArmorQuantumSuit.inventoryTick`. При объединении игрок надевает оригинальный `superbwarfare:ru_helmet_6b47` — исходный `inventoryTick` IC2 не срабатывает, даже когда сам `ItemStack` квантового шлема сохранён в компоненте `techquest_hybrid:donor`.

**Исправление:** `Ic2QuantumHelmetCompat.serverTick` работает для оригинальных шлемов 6Б47, PASGT, M35, объединённых с настоящим IC2 Quantum Helmet. Оно использует оригинальный заряжаемый `ItemStack` из `techquest_hybrid:donor` через `Ic2QuantumChargeManager` и выполняет основные способности квантового шлема:

- **Воздух под водой:** при уменьшении запаса воздуха добавляет до 200 единиц воздуха, расходуя 1 000 единиц энергии IC2 из встроенного Quantum Helmet.
- **Очистка от эффектов:** яд (10 000 × уровень), иссушение (25 000 × уровень), радиация IC2 (10 000 + 100 × усиление); расходы энергии берутся из исходных механик IC2R.
- **Консервы IC2:** при голоде использует штатное `ItemTinCan.onEaten`, а не создаёт еду или дублирует предметы; тратит 1 000 единиц энергии за успешное использование.
- **Ночное зрение:** режим переключается существующим сочетанием IC2 **Alt + клавиша смены режима**. Режим сохраняется в собственных данных шлема и тратит 1 единицу энергии за серверный тик во включённом состоянии. Вместо прежнего принудительного ночного зрения 0.2.4 теперь соблюдается переключатель.
- **Заряд:** MFSU и прочие штатные зарядные устройства продолжают использовать оригинальный `IBackupElectricItemManager` с сохранённым квантовым шлемом; полоска энергии под иконкой и компактный формат `5.07m/10m` сохраняются.

**Не изменено:** оригинальный рендер и текстура 6Б47, зачарования, Apotheosis, наковальня, IC2 MFSU и существующая логика нагрудника 6Б43/джетпака. 0.2.5 **не заменяет** шлем отдельным `ArmorItem`, а только дополняет существующий предмет. Для остальных технических модов (MI/Mekanism/Oritech) интеграция их уникальных шлемных способностей остаётся отдельной задачей.

**Ограничения:** оригинальный IC2 шлем имеет дополнительные HUD-режимы, которые в этой версии не внедрены. Внешний вид остаётся Superb Warfare. Автоматические тесты компиляции не являются игровым тестом.

### Как проверить шлем

1. В отдельном тестовом мире замени один JAR 0.2.4 на 0.2.5; крафтить заново следует только шлемы, полученные до версии 0.2.1, если у них нет `techquest_hybrid:donor`.
2. В кузнечном столе помести **незеритовый шаблон + 6Б47 Superb Warfare + Quantum Helmet IC2**. Проверь название `Квантовая броня IC2 — ...6Б47...`.
3. Помести получившийся шлем в MFSU, проверь увеличение заряда и полоску в инвентаре.
4. Надень шлем, опустись под воду, проверь восстановление воздуха и соответствующее падение заряда.
5. Получи эффект отравления в отдельном мире, проверь, что шлем очистил его и заряд уменьшился.
6. Нажми **Alt + клавиша смены режима IC2** и проверь переключение ночного зрения; без заряда оно работать не должно.
7. Проверь, что после перезахода сохранились заряд, выбор режима, аффиксы, чары и первоначальная 3D-модель.
8. Для 6Б43 повтори проверку джетпака и MFSU — нагрудник не должен измениться.

**Не проверено запуском Minecraft:** требуется ручной клиентский/серверный smoke-test (зарядка, действия IC2, совместимость с Apotheosis). Если Alt+режим не срабатывает в сборке, проверь привязки IC2 в разделе управления и пришли `latest.log`.

## Исправление 0.2.4 — устранён вылет при загрузке Mixin

На реальном клиенте TechQuest с `0.2.3-SNAPSHOT` NeoForge 21.1.264 выдавал:

```text
IllegalClassLoadError:
dev.techquest.hybrid.client.HybridArmorEnergyDecorator is in a defined
mixin package dev.techquest.hybrid.client.* owned by techquest_hybrid.mixins.json
and cannot be referenced directly
```

Это **ошибка аддона TechQuest**, а не Sodium: поздний вылет `Rendering overlay`/
`Sodium's config could not be found` был её вторичным следствием.

Причина: обычный `@EventBusSubscriber` для полоски энергии разместили в
пакете `dev.techquest.hybrid.client`, которым управляет конфигурация Mixin
(для `SuperbWarfareArmorTintMixin`). Mixin запрещает напрямую загружать
классы из собственного пакета, если они не являются применяемыми Mixin.

Исправлено: `HybridArmorEnergyDecorator` перенесён в
**`dev.techquest.hybrid.gui`**, вне пространства Mixin. Существующий
`SuperbWarfareArmorTintMixin` остаётся в исходном пакете; его функциональность
не меняется. В `scripts/test_original_assets.py` добавлена проверка, что
обычный декоратор не возвращается внутрь Mixin-пакета.

**Проверка:** заменить `techquest-hybrid-warfare-0.2.3-SNAPSHOT.jar`
на `techquest-hybrid-warfare-0.2.4-SNAPSHOT.jar`, оставить только один
JAR аддона в `mods`. Запустить тестовый клиент и проверить заряд, пластины
и исходные текстуры. Компиляция/CI не заменяет реальный клиентский smoke-test.

## Новое в 0.2.3 — удобный заряд и пустой HUD бронепластин

- **Сокращённая энергия:** собственная подсказка TechQuest теперь показывает `5.07m / 10m FE` вместо `5072896 / 10000000 FE`. На IC2-гибридах также сокращается исходная строка джетпака вида `5072896/10000000 RF` до `5.07m/10m RF`; название и зачарования других модов не изменяются. `m` — миллион, `k` — тысяча.
- **Полоска заряда в инвентаре:** клиентский `HybridArmorEnergyDecorator` рисует отдельный IC2-подобный голубой индикатор под иконкой всех пяти типов гибридной брони (при пустом заряде остаётся тёмный фон). Если стандартная полоска прочности видна, новая полоска рисуется *над* ней, не скрывая износ.
- **HUD баллистических пластин:** по исходникам Superb Warfare `ArmorPlateOverlay` отображает рамку только если в `minecraft:custom_data` нагрудника присутствует ключ `ArmorPlate`. Поэтому у гибридных нагрудников `6Б43` и `IOTV` на крафте безопасно записывается `ArmorPlate:0.0d`, если поля не было. Ничего не перезаписывается, если пластины уже установлены. Предметы, созданные в 0.2.2, восстанавливают недостающее поле автоматически при ношении (раз в 20 тиков).
- **Уточнение:** 6Б47 — это шлем, но штатный индикатор пластин Superb Warfare работает по предмету слота CHEST, то есть для 6Б43/IOTV, а не для 6Б47. Не путайте этот HUD с новой полоской электричества под иконкой.
- Все оригинальные PNG, 3D-геометрия, кузнечные рецепты, интерфейсы IC2/MFSU и данные Apotheosis остаются без замены.

**Игровая проверка:** после установки 0.2.3 зайди с уже созданным нагрудником 0.2.2, надень его на ~2 секунды и посмотри: тёмная полоска под иконкой до зарядки, голубая полоса при зарядке; HUD Superb Warfare пустой до первой пластины, после вставки пластин заполняется. При повреждении брони должна отдельно показываться стандартная полоска прочности. Проверь статус зарядки IC2 на английском интерфейсе и перезаход в мир. На выделенном сервере и клиенте нужен одинаковый JAR.

## Новое в 0.2.2 — одна батарея IC2 и автоматические названия

### Нативная зарядка квантовых гибридов через IC2 MFSU

Раньше `techquest_hybrid:energy` хранил отдельные 500 000 FE, тогда как IC2 QuantumSuit мог иметь собственный заряд, а прикреплённый электрический джетпак — третью систему. Теперь при **новом объединении**:

- `superbwarfare:ru_helmet_6b47` / PASGT / M35 + `ic2:quantum_helmet`, и `superbwarfare:ru_chest_6b43` / IOTV + `ic2:quantum_chestplate` получают **оригинальную батарею QuantumSuit** из сохранённого `techquest_hybrid:donor`. Её максимальный заряд, уровень допуска (tier), ограничение передачи и количество энергии определяются самим IC2.
- `Ic2QuantumChargeManager` регистрируется как `IBackupElectricItemManager` в штатном `ic2.api.item.ElectricItem` и перенаправляет методы заряда/разряда на встроенный предмет IC2 с сохранением результата в компоненте. Это позволяет IC2 MFSU и другим штатным заряжающим устройствам использовать привычный маршрут IC2, а не принудительно подключать наш FE-аккумулятор.
- На груди при крафте квантового гибрида сохраняется/включается `hasIC2Jetpack`; реакция клавиш полёта и логика IC2 JetpackHandler остаются штатными. Устройство зарядки и джетпак тратят **общую энергию квантового донора**, без её дублирования в другом поле.
- При объединении исходная зарядка квантового нагрудника/шлема **сохраняется** (донор сохраняется вместе со своими DataComponents). Эффекты TechQuest также тратят эту же энергию.
- Для Mekanism/MI/Oritech не меняется текущая экспериментальная `techquest_hybrid:energy` (500 000 FE) и не утверждается наличие полной нативной поддержки их модулей.

При отсутствии IC2 мод не пытается регистрировать его обработчик. Версия `industrial-craft-2-nostalgia-21.1.0-local.26.jar` используется как `compileOnly`, не включается в распространяемый аддон. **Компиляция/API ещё не доказывают, что MFSU зарядил предмет в реальном мире** — нужна проверка.

### Видимое новое имя после кузнечного стола

Результат автоматически получает `minecraft:custom_name`, построенное по локализации:

| Технология | Пример нового названия |
| --- | --- |
| IC2 | `Квантовая броня IC2 — Russian 6B43 Chest` |
| Modern Industrialization | `Квантовая броня MI — Russian 6B43 Chest` |
| Mekanism | `Механизированная броня Mekanism — Russian 6B43 Chest` |
| Oritech | `Экзоброня Oritech — Russian 6B43 Chest` |

Вторая часть берётся **из исходного названия брони**, включая уже имевшееся имя с аффиксами Apotheosis или ручное имя с наковальни. После объединения можно снова переименовать вещь на наковальне. Сохраняются исходный Item ID, текстура и характеристики, меняется только пользовательское отображаемое имя.

**Важно:** это применяется только при **новом** крафте. Ранее полученные 0.2.0/0.2.1 вещи с компонентом `ic2`, но без `techquest_hybrid:donor`, автоматически не преобразуются в квантовый гибрид и не получают новое имя. Не пытайся повторно делать тот же рецепт на старом предмете: для предотвращения дублирования технологии повторный крафт заблокирован.

### Тест в отдельном мире

1. Удали старый JAR `0.2.1-SNAPSHOT` из `mods` и установи `0.2.3-SNAPSHOT`.
2. Через кузнечный стол объедини оригинальный **6Б47 + IC2 Quantum Helmet**; проверь новое название и отображаемую нативную ёмкость IC2, а затем вставь вещь в MFSU. Заряд должен увеличиваться именно в `techquest_hybrid:donor`.
3. Сделай **6Б43 + IC2 Quantum Chestplate**, проверь имя, строку `Electric Jetpack Attached`, заряд через MFSU, расход при полёте и при пассивных эффектах.
4. Проверь `/data get entity @s SelectedItem`, перезаход, наковальню и Apotheosis Reforge; должен сохраниться технический донор, его энергия, аффиксы и кастомное имя.
5. Не применяй к основному миру до реальных client/server smoke tests. Для других технологий пока используйте стандартный заряд через FE.

## Совместимость с текущей сборкой и скриншотами

Основой остаётся **точно оригинальный предмет** Superb Warfare: никакого нового Item ID, UV, PNG, собственной 3D-модели и переопределения стандартного `AnvilMenu`. Это принципиально важно для уже существующих механизмов.

1. **Кузнечный стол (скриншот 1):** теперь используется пользовательский `techquest_hybrid:armor_fusion` (по-прежнему стандартный `RecipeType.SMITHING`). В отличие от прежнего `minecraft:smithing_transform`, он копирует *все данные* оригинальной военной брони и сохраняет весь `ItemStack` технического донора в компонент `techquest_hybrid:donor`. Это сохраняет донорские зачарования, заряд и модули **как данные**; класс технического предмета при ношении остаётся неактивен. **Не путать сохранение данных с подключением всей механики.**
2. **Apotheosis 8.9.0 + Placebo 9.9.4 (скриншот 2):** оригинальная броня остаётся допустимой целью для доступных в Apotheosis систем рефоржа, аффиксов, редкости и сокетов согласно их стандартным ограничениям. Все компоненты *базового левого предмета* копируются без фильтрации, в том числе аффиксы и вставленные камни. Это сохранение данных проверяет код рецепта, но фактическая работа интерфейса Reforge не проверена запуском.
3. **Наковальня (скриншоты 3–7):** никаких кастомных обработчиков наковальни. Левый предмет остаётся основой, правый выступает донором по стандартным правилам Minecraft; чары объединяются только при допустимой совместимости и стоимости. Уже наложенные аффиксы/сокеты и технологический компонент **левого** предмета не заменяются на данные правого. Наковальня **не объединяет** две разных технологических системы и не должна дублировать энергию/заряд. Если обычная наковальня показывает крест/недопустимую стоимость (например, 75 уровней), это может быть связано с несовместимостью, ограничениями ремонта или ванильным порогом Too Expensive, а не с рецептом TechQuest.
4. **Джетпак и зарядка IC2 (скриншоты 8–9):** у оригинальной 6Б43 с уже прикреплённым IC2 джетпаком сохраняется `minecraft:custom_data` с ключом `hasIC2Jetpack` и `charge`. Если к 6Б43/IOTV добавляется `ic2:quantum_chestplate`, мост пытается активировать **нативную attachment-механику** IC2 на результате. Используется `ic2.api.item.ElectricItem.manager` и, для новых квантовых гибридов, зарегистрированный `IBackupElectricItemManager`. Оригинальный менеджер отвечает за уровень допуска и зарядку через MFSU. IC2 получает приоритет перед дополнительной FE capability TechQuest.
5. **Внешность:** оригинальные модели и текстуры Superb Warfare, до получения новых пользовательских моделей и текстур.
6. **Баланс:** броня/прочность/сопротивление пулям исходного предмета пока **не увеличены** при объединении. Модовые модификаторы Apotheosis сохраняются как есть; нет суммирования защитных значений SBW + квантовый нагрудник. Перед реализацией итоговых чисел предлагается правило **max(base, donor)** для базовой брони/прочности (без суммирования), отдельно от аффиксов и особых сопротивлений.
7. **Другие технологии:** встроенный оригинальный предмет-донор сохраняет данные MekaSuit/Modern Industrialization/Oritech, но **не запускает** их специфические алгоритмы автоматически. Это пока требует отдельных адаптеров — нельзя считать их модули рабочими.

**Важное ограничение IC2:** механика сверена с открытым кодом JetpackHandler в IC2R 1.21.1, где используется `hasIC2Jetpack` и `ElectricItem.manager`. В вашей зафиксированной `industrial-craft-2-nostalgia-21.1.0-local.26.jar` эту совместимость нужно проверить непосредственно в Minecraft. API закреплённого JAR проверен при компиляции, но фактическая работа зарядки и полёта требует проверки в игре. Прямая зарядка MFSU через стандартную IC2-систему должна оставаться собственностью IC2.

## Что происходит с оригинальной бронёй

- Оригинальные предметы и модели остаются у Superb Warfare 0.8.9.2: `ru_helmet_6b47`, `ru_chest_6b43`, `us_helmet_pasgt`, `us_chest_iotv`, `ge_helmet_m_35`.
- **Никаких новых PNG, моделей, иконок и самодельных комплектов.** Включённый в JAR Superb Warfare оригинальный Bedrock-рендер и его собственные текстуры используются как раньше.
- 20 рецептов custom Smithing Fusion: незеритовый шаблон + базовый предмет SBW + соответствующая техноброня IC2 Nostalgia / Modern Industrialization / Mekanism / Oritech → **тот же item ID** с данными `techquest_hybrid:technology`.
- Рецепт наследует компоненты базового предмета, включая зачарования, износ, `ArmorPlate` и уже имеющуюся отделку. Дорогой предмет-донор **расходуется**, но его оригинальный ItemStack и компоненты сохраняются во встроенном snapshot, при этом его нативные механики требуют отдельной интеграции. Обязательно проверить ID доноров, в частности IC2 local.26.

## Новое в 0.2: реальная механика энергии и улучшений

Добавлены компоненты `techquest_hybrid:energy` и `techquest_hybrid:donor` и стандартная **NeoForge FE capability** для пяти оригинальных предметов SBW *только при наличии улучшения*. Максимальная ёмкость — **500 000 FE**, заряд за одну операцию приёма — до **8 000 FE**. Для IC2 Quantum Hybrid вместо этого FE-лимита используется ёмкость и заряд родного QuantumSuit; его можно пробовать заряжать IC2 MFSU.

**Новый не-IC2 гибрид после ковки имеет 0 FE** — энергия не появляется из воздуха и не копируется с донора. Пока не заряжен, техноэффекты отключены. Сервер раз в 20 тиков тратит FE из предмета и обновляет эффекты:

| Технология | Шлем с энергией | Бронежилет с энергией | Совпадающая пара |
| --- | --- | --- | --- |
| IC2 Nostalgia | Ночное зрение + дыхание под водой, −80 FE/с | Сопротивление I, −150 FE/с | Огнестойкость, дополнительно −40 FE/с на предмет |
| Modern Industrialization | Ночное зрение, −90 FE/с | Сопротивление I, −130 FE/с | Сопротивление II, −40 FE/с на предмет |
| Mekanism | Дыхание под водой, −70 FE/с | Сопротивление I, −120 FE/с | Дыхание под водой, −40 FE/с на предмет |
| Oritech | — | Скорость I, −90 FE/с | Скорость II, −40 FE/с на предмет |

**Важно:** это работающие эффекты TechQuest с энергорасходом, но **не полная копия оригинальных EU-механик IC2, модулей MekaSuit, квантового прыжка, джетпака и т.п.** В этой первой версии для улучшения сохранён только технологический тип: система энергоснабжения основана на FE; поддержка конкретных зарядных станций, передача заряда и уникальных модулей доноров — отдельная задача.

### Текст подсказки

В подсказке оригинального предмета теперь будут показаны:
- технология (например, **IC2: Nostalgia**),
- **энергия FE / 500 000** и подсказка о зарядке,
- краткая функция комплекта,
- цвет материала отделки, если применён Armor Trim.

Есть русская и английская локализация. Старое имя предмета, иконка и описание Superb Warfare остаются.

## Перекраска шаблонами без новых PNG

В тег `minecraft:trimmable_armor` включены **пять оригинальных предметов**. В кузнечном столе используй **ванильный шаблон Armor Trim** + исходную SBW броню + подходящий материал (железо/медь/лазурит/алмаз/изумруд/золото/кварц/редстоун/аметист/незерит). Это **отдельно** от апгрейда технологией.

Client-only mixin изменяет передаваемый в оригинальный Bedrock-рендер **цветовой множитель**, а не байты оригинальной PNG. Реальная 3D-текстура сохраняется; материал Trim выбирает оттенок. Орнамент шаблона не переносится на нестандартную геометрию: сейчас это **перекраска общей тональности**, не узор. Никакого нового пакета текстур нет.

В присланном пользователем JAR `superbwarfare-0.8.9.2-mc1.21.1-c22d98c2.jar` найден именно встроенный SimpleBedrockModel **2.5.1.1** с методом `GeoArmorRendererV2.renderToBuffer(PoseStack, VertexConsumer, int, int, int)`. Это подтверждает цель mixin на уровне байткода, **но не доказывает, что перекраска видна в запущенной игре**.

## Проверка на отдельном мире

1. Положи собранный JAR **0.2.3-SNAPSHOT** в тестовый профиль. Удали старые JAR `0.1.0-SNAPSHOT` и `0.2.0-SNAPSHOT` из `mods`, чтобы не было дубликатов.
2. В творческом мире проверь обычное объединение IC2-шлема. Наведи мышь — должны появиться технология и энергия 0/500000 FE. Попробуй FE-зарядник.
3. Для диагностики энергетических эффектов без поиска подходящей зарядки используй следующие команды **в игровом чате (с правами команд)**:

```mcfunction
/give @s superbwarfare:ru_helmet_6b47[techquest_hybrid:technology="ic2",techquest_hybrid:energy=500000]
/give @s superbwarfare:ru_chest_6b43[techquest_hybrid:technology="ic2",techquest_hybrid:energy=500000]
```

Надень обе вещи: проверь ночное зрение, дыхание под водой, сопротивление и огнестойкость. Подожди 10–20 секунд, снимай/надень броню — число FE должно уменьшаться только на сервере.

4. Отдельно проверь **Armor Trim template + материал** на шлеме и жилете. Если изменился только tooltip, а цвет нет, пришли `latest.log` и скриншот с видом от третьего лица.
5. После выхода и повторного входа проверь сохранение `techquest_hybrid:energy`, `technology`, `minecraft:trim`, `ArmorPlate` и зачарований; также проверь выделенный сервер с аддоном на обеих сторонах.

## CI и границы готовности

```bash
cd addons/hybrid-warfare-armor
python scripts/generate_assets.py
python -m unittest discover -s scripts -p 'test_*.py' -v
gradle build
```

GitHub Actions компилирует JAR, валидирует рецепты/локализации и проверяет, что **ни один PNG или кастомная 3D-модель** не добавлены. **Это не игровой smoke-тест.** Не сливать с `main` и не добавлять в installer до ручной проверки пользователя.
