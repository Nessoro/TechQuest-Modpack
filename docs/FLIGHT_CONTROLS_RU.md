# Геймпад только для самолёта — уточнение #13

Владелец уточнил 08.11.2026: Xbox/джойстик нужен для пилотирования самолёта вместо неудобного управления мышью. Ходьба, меню, инвентарь и остальные действия остаются на мыши и клавиатуре. **Авиационная интеграция пока не реализована и не проверена запуском Minecraft.**

## Проверенная основа

В уже включённом Superb Warfare 0.8.9.2 есть `A10Entity` и данные `data/superbwarfare/sbw/vehicles/a_10a.json`, включая кресло `Pose: Pilot`. Это первая цель для адаптера; добавлять ещё один авиамод ради проверки устройства не требуется.

Исследован существующий JAR `superbwarfare-0.8.9.2-mc1.21.1-c22d98c2.jar`, SHA256 `c06b4da8258adbc7d623c5c8e36ffc642c28831ddf6c9aa9c05c10dd18997490`. Статический просмотр сигнатур через Java 21 javap выявил:

- `VehicleEntity.mouseInput(double, double)`, `processInput(short)`, `getSeat(Entity)` — кандидаты для дальнейшего изучения клиентского ввода и проверки кресла.
- `ClientMouseHandler` содержит `mouseXMoveTick`/`mouseYMoveTick`; `ControlConfig` — инверсию авиационного управления и чувствительность мыши.
- `VehicleMovementMessage(short keys)` передаёт битовую маску, а не четыре аналоговые оси. Само наличие метода `mouseInput` не доказывает назначение его параметров или достаточность для сетевой синхронизации.

В проверенных настройках Controlify 3.0.1 не найден готовый контекст «пилот самолёта». Поэтому Controlify и добавленная для него YACL исключены из обязательного состава. Их опубликованные метаданные сохранены отдельно в `compat/client-controls/controller-research.json`. Успех Windows SDL3 smoke-test относится только к загрузке библиотеки кандидата, без игры, устройства или авиационных осей.

## Следующая реализация

1. Проследить вызовы ввода и сетевую передачу именно закреплённого Superb Warfare: какая ось задаёт крен/тангаж, как задаются рыскание и тяга, какие действия дискретны. Не менять напрямую положение/скорость самолёта в обход его физики.
2. Проверить возможность небольшого клиентского адаптера NeoForge, читающего Xbox через уже доступный Minecraft LWJGL GLFW. Это исследуемый вариант, не готовая функция. Для нестандартного джойстика отдельно нужны сведения о его осях и кнопках.
3. Активировать адаптер только для локального игрока в кресле пилота поддерживаемого самолёта, при фокусе окна и закрытом меню. Сбрасывать состояние при выходе, смерти, смене мира, открытии меню, потере фокуса и отключении устройства. Не эмулировать глобально WASD или движения мыши.
4. Добавить настройки в игре: включение авиационного ввода, устройство, калибровка/мёртвые зоны, чувствительность, инверсия, оси и кнопки. Не требовать Python или консоль. Сохранять клавиатуру и мышь как доступный способ управления самолётом.
5. Сначала проверить вход/выход из кресла и отсутствие команд вне самолёта, затем руление/взлёт/полёт/посадку, одновременные оси, нейтраль, отключение устройства и сохранение настроек. Повторить с сервером и измерить время кадра на слабом ПК.

Кандидат исходной раскладки Xbox, требующий проверки: левый стик — крен/тангаж, правый по горизонтали — рыскание, триггеры — изменение тяги. Не считать эту схему включённой или подтверждённой до реализации и испытания физическим устройством.
