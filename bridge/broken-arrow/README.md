# TechQuest Bridge — Broken Arrow × Minecraft (research / MVP)

**Статус:** проектирование. Рабочая ветка: `experiment/broken-arrow-bridge-mvp`. Основная сборка `main` не меняется. Рабочего межигрового моста пока нет.

## Концепция (обновлена 14.11.2026)

Broken Arrow — стратегическое командование, Minecraft TechQuest (1.21.1, NeoForge 21.1.264) — поле боя от первого лица. Командир сможет **вызывать подразделения** (пехоту, наземную технику, позднее авиацию), выдавать приказы и получать сведения о выполнении. Minecraft-игрок участвует в бою непосредственно.

**Захват территорий исключён из проекта.** Нет секторов, зон владения, процентного контроля деревни, таймеров захвата территории и очков за удержание района.

**Здания остаются:** пехота может занимать, защищать и освобождать конкретное здание. Изменение гарнизона/контролирующей стороны фиксируется по фактическому присутствию внутри здания и передаётся командиру. Это не захват территории.

## Порядок MVP

1. Исследовать официальные возможности Scenario Editor/LuaNode Broken Arrow для передачи приказов наружу, без вмешательства в клиент или античит. Возможность сетевого I/O до сих пор не подтверждена.
2. Создать независимый Bridge Server + companion UI (без модификации Broken Arrow) с приказами `deploy`, `move`, `defend_building`, `garrison_building`, `evacuate_building` и состоянием подразделений/зданий.
3. Создать отдельный серверный NeoForge-мод `techquest_bridge`: реестр `unit_id`, `building_id`, управление вызванными игровыми сущностями и сохранение состояния в мире.
4. На испытательном сервере проверить пригодность существующего Superb Warfare 0.8.9.2 и кандидатов на управляемую NPC-пехоту/экипажи. Наличие публичного API для командования **не проверено**; пока нет его подтверждения, не обещать работающий `deploy` или AI `move`.
5. Прототип: 1 деревня / небольшой посёлок, 2–4 здания с гарнизонами, 2 отделения пехоты, 1 единица техники при подтверждённой совместимости. Командир видит статус каждого здания, **без владения территорией**.
6. Только затем — авиационные единицы, продвинутая генерация поселений и вторичные авиаудары Incoming 3.10.4.

## Генерация зданий

- На первом этапе использовать существующую деревню или тестовые шаблоны зданий, помеченные уникальным `building_id`.
- По результатам теста рассмотреть datapack изменения частоты генерации деревень только в новых чанках либо отдельные шаблоны жилых/военных построек.
- Не менять глобальную генерацию мира TechQuest в `main` ради эксперимента.

## Ограничения

- Никакой DLL-инъекции, чтения памяти Broken Arrow, перехвата его сетевого протокола или обхода античита.
- Не заменять и не удалять существующие моды; не править `modlist.json` или установщик без последующего согласованного этапа.
- При отсутствии документированного разрешённого внешнего I/O в Broken Arrow использовать companion UI; он не является встроенной панелью Broken Arrow.
- Команды проверяются на сервере; повторные операции не создают дубликаты юнитов, вызов ограничен лимитами производительности и разрешённой игровой областью.
- Не утверждать, что здания могут автоматически становиться гарнизонами без реализации ИИ, навигации и проверки совместимости с модами.
