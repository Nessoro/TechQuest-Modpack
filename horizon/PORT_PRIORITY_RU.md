Источник: официальный `horizon-port-pack`, workflow [#42381294122](https://github.com/Nessoro/TechQuest-Modpack/actions/runs/42381294122), снимок исходной экспериментальной TechQuest 0.3.3 из Build #42372848633. ## Шесть кандидатов на перенос данных (не полный порт)

| Мод | Лицензия по инвентаризации Horizon | Решение |
| --- | --- | --- |
| YUNG's Better Dungeons | LGPL-3.0-only | **Первый тест**, workflow `horizon-yung-dungeons.yml` |
| YUNG's Better Strongholds | LGPL-3.0-only | Следующий после теста Dungeons |
| YUNG's Better Mineshafts | LGPL-3.0-only | Последующий |
| YUNG's Better Nether Fortresses | LGPL-3.0-only | Последующий |
| Terralith | LicenseRef-Stardust-Labs-License | Требует отдельного лицензионного анализа |
| When Dungeons Arise | All Rights Reserved | Только локальная проверка; не распространять перенесённые ассеты без разрешения |

Важно: статус data-tier означает, что инструмент способен перенести **некоторые данные** при наличии JAR. Это не гарантия готовых структур в игровом мире; необходимо тестировать datapack-форматы, блоки, лут, зависимости и генерацию Horizon 26.3. Чужой мод/архив нельзя автоматически объявлять разрешённым к публикации.

## Что нельзя считать текущим портом

- **Wyrmroost и огромные монстры** — Horizon относит к deep-tier (мобы, анимации, ИИ, модели). Потребуется полноценная нативная реализация, не `.hmod` с ресурсами.
- **Create, Mekanism, BuildCraft, IC2** — текущие Java-механики на Rust не перенесены. BuildCraft классифицирован в machines-tier; Create/Mekanism могут также зависеть от deep API.
- **Forgematica и Xaero** — отдельный клиентский функционал и рендер; Java JAR не запускаются.
- **Incoming** и вручную закреплённый **IC2 Nostalgia** остались неклассифицированными в официальном отчёте: для оценки нужны разрешённые исходные JAR/метаданные и отдельный анализ.

## Обязательный критерий готовности

Для каждого выбранного модa: 1) законный исходник или авторский JAR для локальной проверки; 2) проверенный `hmod`/ресурсы с воспроизводимым источником и указанием лицензии; 3) сравнение структуры, генерации, лута, серверной загрузки и игры на Horizon 26.3; 4) тестирование мультплеера; 5) только потом считать мод частично/полностью перенесённым.

Отчёт был получен без скачивания и запуска каких-либо сторонних Java JAR, а значит подтверждает только классификацию Modrinth/манифеста.

Перенесённые данные и чужие JAR **не опубликованы**, в артефакте доступен лишь отчёт [Coverage-ONLY](https://github.com/Nessoro/TechQuest-Modpack/actions/runs/42382390837/artifacts/13578440342).

Это **не подтверждённый игровой порт**: не проверялись загрузка в реальном Horizon 26.3, генерация/совместимость структур, YUNG API, поведение процессоров, сервер и Tailscale. Для перехода от `partial` к `ported` нужны отдельные тесты, подтверждение прав на распространение и игровые сравнения.
