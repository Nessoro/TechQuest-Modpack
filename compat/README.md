# Исправления совместимости TechQuest

Исправления рассчитаны на Minecraft 1.21.1 / NeoForge 21.1.259 и IC2 Nostalgia
21.1.0-local.26. После обновления модов нужно повторять серверный и клиентский тесты.

## Iris и Sodium

В `modlist.json` закреплены Modrinth version IDs:

- Iris 1.8.12: `t3ruzodq`.
- Sodium 0.6.13: `Pb3OXVqC` — точная обязательная зависимость этого выпуска Iris.

Сборщик теперь учитывает `version_id` зависимостей и явные `version_id` в списке
модов. При противоречащих точных требованиях сборка завершается ошибкой;
неподходящая новая версия больше не подставляется автоматически.
Повторная сборка очищает устаревшие JAR в генерируемых `output/client/mods`
и `output/server/mods`. Свои дополнительные моды храните в `manual-mods/`.
Остальные незакреплённые моды по-прежнему выбираются из актуальных выпусков.

## Create и IC2 Nostalgia

`techquest-compat/` содержит исходники нашего мода с ресурсами без Java-кода.
Сборщик создаёт `techquest-compat-1.0.0.jar`, устанавливает его клиенту и серверу
и помещает в `overrides/mods/` внутри `.mrpack`. Штатный серверный установщик
также извлекает этот мод. Он загружается после Create и IC2, поэтому исправления
применяются ко всем мирам, включая уже существующие.

- Шесть рецептов плавки/переплавки Create заменяют неверные `ic2:ingot_tin`,
  `ic2:ingot_silver`, `ic2:ingot_uranium` на `ic2:tin_ingot`,
  `ic2:silver_ingot`, `ic2:uranium_ingot`.
- Два рецепта для `ic2:ingot_aluminium` отключены: такого слитка в используемом
  IC2 Nostalgia нет. Рецепты алюминия для других модов не изменяются.
- Create закреплён на проверенном выпуске 6.0.10 (`UjX6dr61`).

## Superb Warfare на выделенном сервере

В оригинальном Superb Warfare 0.8.9.2 (`bl7W8fjU`) `ClientLevelMixin` указан
одновременно в общем списке `mixins` и клиентском списке `client`.
Сервер пытается загрузить клиентский класс и пишет ошибку `invalid dist`.

После проверки SHA-512/SHA-1 исходного скачивания сборщик и серверный установщик
локально удаляют только запись `ClientLevelMixin` из общего списка в
`mixins.superbwarfare.json`. Клиентский список и все остальные записи JAR
остаются неизменными. Повторное применение безопасно. Неожиданная структура
конфига и подписанные JAR отклоняются.

В репозитории нет изменённого стороннего JAR. Клиент и download manifest
используют оригинальный файл автора. SHA серверной производной копии отличается
от SHA исходного скачивания: это ожидаемый результат исправления. Для установки
сервера используйте `scripts/install_server.py` или `output/server`, поскольку
обычный импорт `.mrpack` сторонним серверным инструментом не применит этот шаг.

## Проверки

`python -m unittest discover -s tests -v` проверяет точные зависимости, упаковку
рецептов, их установку на сервер и точечное изменение mixin-конфига.
`python build_pack.py` собирает клиент и сервер с проверкой хешей скачиваний.
Workflow `smoke-server.yml` отклоняет повторное появление исправленных ошибок
рецептов и `ClientLevelMixin`, даже если сервер достиг состояния `Done`.

Графический запуск, шейдеры, подключение игроков и длительная игра требуют
отдельной проверки. Успешный серверный smoke-test не подтверждает их.
