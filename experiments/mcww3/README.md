## Сделанный первый шаг

`inspect_bundle.py` читает оригинальный ZIP/JAR: метаданные Forge, зависимости, заявленную
лицензию, наличие исходников/build-файлов, количество классов, версии байткода, обращения
к пространствам Forge/Minecraft/Distant Horizons/LWJGL. Классы не исполняются и не
декомпилируются; модели, звуки и исходные файлы не входят в отчёт.

```sh
python -m unittest discover -s experiments/mcww3/tests -v
python experiments/mcww3/inspect_bundle.py --bundle /path/to/original.zip --report /tmp/preflight.json
```

Нужен Python 3.11+ только разработчику. Обычный пользователь TechQuest продолжает пользоваться
Windows EXE и официальным Minecraft Launcher.

Workflow `.github/workflows/mcww3-preflight.yml` скачивает оригинальный авторский ZIP по HTTPS
во временную папку GitHub runner и публикует **только JSON метаданных**. SHA-256 в отчёте
вычислен после скачивания; это наблюдаемый хеш, не независимая сверка с авторским checksum.
Успех workflow не означает компиляцию или работоспособность порта.

1. Установить точную версию исходников и условия изменения кода/ассетов. Проверить Gradle,
   исходные зависимости, mappings, лицензии и возможность воспроизводимой сборки 1.20.1.
2. Перенести сборку на Java 21 / NeoForge 21.1.264. Затем адаптировать регистрации, события,
   конфиги, entity/item/block API и сетевые пакеты Minecraft 1.21.1.
3. Отдельно адаптировать рендер glTF, HUD, камеры, звук, физику и интеграцию с Distant Horizons.
   API DH для другой версии Minecraft нельзя считать автоматически совместимым.
4. Сохранить формат и идентификаторы контент-паков либо реализовать явную миграцию.
   Проверить сериализацию, сохранения, клиент/сервер и одинаковые версии паков.
5. Проверить минимальную отдельную инсталляцию: меню, спавн техники, управление, полёт,
   сервер и вход игрока. Затем интеграцию с Incoming, Superb Warfare, TaCZ, Sodium, Create,
   Xaero и управление; измерить FPS/TPS/RAM на слабом ПК.
6. Только после этих проверок подключать эксперимент к отдельному тестовому профилю
