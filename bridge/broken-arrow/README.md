# TechQuest Bridge — Broken Arrow × Minecraft (research / MVP)

Статус: **исследование и проектирование; НЕ рабочая интеграция**. Рабочая ветка: `experiment/broken-arrow-bridge-mvp`. Основная сборка `main` не меняется.

## Цель

Один игрок находится в Broken Arrow как командир; второй играет на отдельном сервере Minecraft TechQuest (Minecraft 1.21.1 / NeoForge 21.1.264). Командир должен выдавать авиационную поддержку, а сервер Minecraft исполнять её через штатный Incoming 3.10.4 и возвращать проверяемый статус операции.

## Обязательные границы

- Не меняем `modlist.json`, установщик TechQuest и его библиотеки до отдельного решения о включении моста. Не вводим новый обязательный мод.
- Не патчим `BrokenArrow.exe` / игровые DLL, не внедряем код, не используем чтение памяти, перехват сетевых пакетов, античит или автоматизацию игрового ввода.
- Не изменяем код Incoming и не копируем его JAR. Интеграция первой версии — через штатную серверную команду с явным списком разрешённых типов ударов.
- Сетевые команды выполняются только после проверки роли, мира, координат, времени, лимитов и полномочий. Ядерные удары выключены и не входят в MVP.
- Результат «команда принята» не считается доказательством попадания по цели.

## Состав

- `docs/FEASIBILITY_RU.md` — проверенные факты, неизвестные возможности Broken Arrow и план легальной проверки через встроенный редактор.
- `docs/MVP_ARCHITECTURE_RU.md` — топология, сценарий взаимодействия, безопасность, статусы, тестирование.
- `protocol/strike-order.schema.json` — стартовая схема заявки, НЕ реализованный API.

## Два варианта соединения

**A — полный**, только если встроенный сценарный API Broken Arrow официально умеет обмениваться данными с внешним сервисом: LuaNode → разрешённый системный API → Bridge Server → NeoForge Bridge Mod.

**B — гарантируемый независимый путь (цель первого исполнимого прототипа)**: командир играет в Broken Arrow, но подтверждает запросы и посылает удары через отдельную веб-панель / локальное companion-приложение. Broken Arrow не модифицируется, а редактор сценариев может использоваться отдельно для создания тематической миссии. В таком режиме результат возвращается на companion-панель, **не внутрь интерфейса Broken Arrow**.

## Следующие этапы

1. Провести read-only проверку Help → LuaNode / GameAPI в установленной Broken Arrow: HTTP, сокеты, `io`, файлы, IPC, события, политика EAC. Ничего не обходить. Если поддержка не документирована, оставаться на пути B.
2. Реализовать Bridge Server с операциями `request → approve → dispatch → result` и role-based auth.
3. Реализовать отдельный NeoForge мод `techquest_bridge`, отключённый по умолчанию. Сетевой ввод — не на серверном тике; вызов команды Incoming — только в серверном треде.
4. Провести локальную симуляцию и испытания только в копии мира, затем проверить с двух ПК.
5. Отдельно обсудить opt-in подключение моста к установщику TechQuest (не раньше полного тестирования).
